기존 포트폴리오 용도로 작업했던 프로젝트를 리뉴얼하며 정보 전달 방식과 사용자 경험을 재설계하고, 유지보수와 확장을 고려한 코드 구조를 만드는 것을 목표로 했다.
단순 결과 나열이 아닌, 각 프로젝트의 문제점과 개선 방향을 정리하고 구조적으로 보완하는 과정에 집중했다.

1. 배경 / 문제점 (Background)

기존 포트폴리오는 하나의 페이지 안에 콘텐츠를 나열하는 구조로, 정보의 중요도나 사용자 행동 흐름이 명확하게 드러나지 않았다.
또한 각 페이지가 개별 HTML 파일로 구성되어 있어 공통 요소 수정 시 반복 작업이 발생했고, 프로젝트가 늘어날수록 구조 확장에 한계가 있었다.

  • 콘텐츠가 단순 나열되어 정보 흐름과 우선순위가 명확하지 않음
  • 정적 페이지 구조로 인해 유지보수 비용 증가
  • 공통 UI 요소 관리가 어려움
  • PC 중심 설계로 모바일 환경에서 가독성과 조작성이 떨어짐

2. 목적 (Goal)

  • 코드 구조 개선
    공통 컴포넌트 분리와 SPA 구조 도입을 통해 유지보수와 확장이 쉬운 구조를 만드는 것을 목표로 했다.
  • 사용자 흐름 최적화
    정보 전달 → 이해 → 행동으로 이어지는 자연스러운 사용자 흐름을 기준으로 콘텐츠를 재배치했다.
  • 반응형 및 UI 일관성 확보
    모바일 퍼스트 기준으로 레이아웃을 재정의하고, 페이지 전반의 UI 규칙을 통일했다.
  • 포트폴리오 완성도 향상
    단순 결과물이 아닌, 구조 설계와 코드 관리 역량을 함께 보여주는 포트폴리오를 완성하고자 했다.

3. 방향성 (Direction)

이번 리뉴얼은 디자인을 새롭게 만드는 것보다 사용자 경험과 내부 구조 개선에 초점을 맞췄다.
기존 UI 스타일은 최대한 유지하되, 페이지의 목적과 사용자 행동을 기준으로 콘텐츠 구조를 재정리했다.

  • 디자인 변경 최소화, 구조와 흐름 개선 우선
  • 페이지 전환 없는 SPA 구조 적용
  • 공통 레이아웃과 컴포넌트 중심 설계
  • 모바일 환경을 기준으로 한 UX 설계

4. 범위 (Scope)

리뉴얼의 범위를 명확히 정해 불필요한 작업을 줄이고, 구조 개선이라는 목적에 집중했다.

  • UI 디자인 전면 변경 ❌
  • 관리자(Admin) 기능 리뉴얼 ❌
  • 페이지 구조 리팩토링 및 SPA 전환 ⭕
  • 공통 컴포넌트 분리 ⭕

이번 리뉴얼은 단순히 화면을 새로 꾸미는 작업이 아니라, 포트폴리오를 하나의 실제 서비스처럼 구조적으로 재설계하는 과정이었다.
이를 통해 사용자 경험과 코드 구조를 동시에 고려하는 작업 방식을 정리하고, 향후 프로젝트에도 적용할 수 있는 기준을 마련하고자 했다.
