Table

개요

Table 컴포넌트는 데이터를 구조화하여 시각적으로 정리하고 비교할 수 있도록 도와주는 UI 요소입니다. 정보를 표 형식으로 명확하게 전달하며, 사용자가 데이터를 빠르게 파악할 수 있도록 설계됩니다.

핵심 특징

  • 데이터와 정보를 정리하여 가독성을 높임
  • 열과 행을 활용해 계층/관계 표현 가능
  • 반복되는 데이터, 비교 항목 등 구조화에 최적화
  • 스타일보다 정보 구조 중심

구조 유형

  • 기본 표 - 단순 데이터 나열
  • 헤더 포함 표 - 카테고리/속성 구분
  • 행 강조 표 - 특정 행 강조 표시

유형

Table 컴포넌트는 목적과 데이터 형태에 따라 다양한 구조로 사용될 수 있습니다. 아래 예시는 일반적인 사용 사례를 기준으로 정리한 것입니다.

기본 표

Dot (기본)

단순 데이터 나열용 표입니다. 기본적인 열과 행으로 정보를 정리하며, 설명 문단과 함께 데이터 항목을 비교할 때 유용합니다.

기본 데이터 표
항목 설명 예시
제품명 상품 이름 사과
수량 구매 수량 10

Dash (하위 구조)

하위 항목이나 세부 데이터가 포함된 표입니다. 상위 카테고리와 관련된 세부 정보를 나열할 때 사용하며, 계층 구조를 명확히 표현할 수 있습니다.

하위 구조 데이터 표
카테고리 항목 상세
과일 사과 빨간색, 신선함
과일 배 노란색, 달콤함

가이드라인

Table 컴포넌트는 단순한 시각 요소가 아니라 데이터 구조를 명확하게 전달하는 UI입니다. 따라서 스타일보다 정보 구조를 기준으로 선택해야 합니다.

같은 데이터라도 목적과 컨텍스트에 따라 적합한 표 형태가 달라질 수 있으므로, 사용 시 항상 “무엇을 전달하고자 하는가”를 먼저 판단해야 합니다.

권장 (Do)

데이터 구조를 명확하게 전달할 수 있는 표 형태로 작성합니다.

  • 헤더와 행을 활용해 카테고리/속성을 구분
  • 한 페이지 내 표 역할 일관성 유지
  • 중복 데이터와 항목을 최소화하여 가독성 확보
  • 행/열 내부 항목은 동일 레벨 유지
  • 스타일보다 정보 전달 중심

금지 (Don't)

표를 레이아웃 용도로 사용하는 것은 지양합니다.

  • 디자인 목적의 임의적 표 사용
  • 버튼/카드 UI를 표로 강제 구성
  • 스타일 혼용으로 의미 전달 혼란
  • 그리드 레이아웃 대용으로 표 사용
  • 불필요한 중첩 구조 생성

디자인 원칙

  • 의미 우선 - 스타일보다 정보 구조
  • 일관성 - 동일 정보는 동일 구조
  • 명확성 - 구조는 단순하게 유지

접근성

Table 컴포넌트는 HTML 시맨틱 구조를 기반으로 동작해야 하며, 스크린 리더에서도 동일한 데이터 구조로 인식되어야 합니다.

시각적 스타일은 변경 가능하지만, 정보 구조 자체는 유지되어야 합니다.

시맨틱 규칙

  • <table> - 데이터 그룹
  • <thead> - 열 제목
  • <tbody> - 데이터 행

표 구조는 반드시 HTML 기본 요소를 사용해야 하며, div 기반 구현은 금지됩니다.

스크린 리더 동작

  • 헤더와 행을 기반으로 데이터 구조를 안내
  • 열/행 순서를 정확히 인식
  • 합계나 요약 데이터는 별도 설명 포함

인터랙션 기준

  • 링크/버튼 포함 시 키보드 접근 가능
  • 셀 클릭 이벤트 사용 최소화
  • 포커스 순서는 DOM 구조를 따라야 함

주의 사항

  • div로 표 구조를 흉내 내지 않기
  • 그리드 레이아웃 대신 ul/ol/table 사용 금지
  • 시각적 표현만으로 데이터 구조 전달하지 않기
